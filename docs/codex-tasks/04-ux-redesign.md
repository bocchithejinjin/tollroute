# Codex タスク 04: UI/UX の見直し（調査 → 設計 → 実装）

## 背景
`tollroute/` は「高速代の予算内で、いちばん早く・お得に着くルート」を出す Django アプリ（自分用・ローカル）。
利用者（このアプリの持ち主）から「UI/UX がイケてない。どうしたら使いたくなるか考えてほしい」と依頼があった。

今の画面: `routes/templates/routes/index.html`（Bootstrap 5 + Chart.js、1 ファイル）。API: `GET /api/search/`（`routes/views.py`）。
画面に出しているもの: 条件フォーム（出発地・目的地＝駅の選択か住所か緯度経度、出発日時、予算）、予算内のおすすめ最大 5 ルート
（ラベル: 最速 / いちばんお得 / 安さ重視 / ほかの候補、所要時間・到着時刻・高速代・一般道だけより何分早いか・お得度 円/分、
道順、料金の内訳と割引、Google マップ / Yahoo!カーナビで開くボタン）、出発時刻をずらすと安くなる提案、予算と所要時間のグラフ、
全候補の表、一般道だけの基準時間、概算である旨の注記。地図は利用者の希望で出さない（ナビアプリに渡す）。

## やること
1. **調査（web 検索を使ってよい。出典 URL 必須）**: 評判のよい経路・料金系の UI を調べる。例: 乗換案内（ジョルダン、NAVITIME、Yahoo!乗換案内、Google マップの経路比較）、
   カーナビアプリ（Yahoo!カーナビ、Google マップの有料道路回避の UI）、料金比較・旅行予約（Skyscanner の「最安・最速・おすすめ」タブ、Google Flights の価格グラフ）、
   NEXCO ドラぷらの料金検索、そのほか「選択肢を比べて決める」UI のベストプラクティス（比較カード、トレードオフの見せ方、モバイルの片手操作）。
2. **設計**: 「誰が・いつ・どこで・どんな気持ちで使うか」（例: 出発前に自宅でスマホから、急いでいる、予算はざっくり）から考え、
   使いたくなる理由と、今の画面の問題点を整理し、改善案を決める。迷わず 1 つ選べること、最初の 1 画面で答えが分かること、入力の手間を減らすこと
   （よく使う出発地・目的地、予算の決め方、「今すぐ」）、スマホで見やすいこと、を重視。AdminLTE は必須ではない（教材の都合で挙げていただけ）。
   使いやすさを優先して構わない。外部 CDN の読み込みは今と同程度なら可（固定バージョン）。
3. **実装**: `routes/templates/routes/index.html` を中心に反映する。必要なら静的ファイル（`routes/static/routes/` に CSS/JS）へ分割してよい
   （その場合 `config/settings.py` の静的ファイル設定も確認）。ブラウザの localStorage でよく使う地点などを覚えるのは可（try/catch で囲む）。
   API の応答に足りない情報があれば `routes/views.py` に**追加**してよいが、既存のキーは消さない・意味を変えない。`engine/` は変更しない。
4. **テスト**: `routes/tests/` の既存テストが通ること。追加した API の項目があればテストを足す。可能なら
   `docker compose -f .devcontainer/compose.yaml exec -T app pytest -q` を実行して結果を報告（Docker に繋がらなければ、その旨を報告）。

## 成果物
- `docs/ux-redesign.md`: 調査結果（出典付き）、想定利用者と利用場面、今の画面の問題点、採用した改善とその理由、見送ったものと理由。日本語。
- 画面の実装。git のコミットはしない。最後に、変更したファイルの一覧と、主な改善点を 5 行程度で報告。

## 守ること
- 料金・時間は概算である旨と、「近似の結果」の警告（API の `approximate`）は、目立ちすぎず見落とされない形で残す。
- ユーザーの入力を外部サービスに送らない（ナビアプリを開くリンクは、利用者が押したときだけでよい）。
- 文言は日本語で、短く、平易に。
