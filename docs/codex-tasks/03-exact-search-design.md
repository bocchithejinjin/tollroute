# Codex タスク 03（設計の相談、コード変更なし）: 時刻で料金が変わるときの、正確で速い探索

## 背景
`engine/search.py` は多目的ラベル法。正確さのため、料金が切り替わる時刻（深夜割引 0 時・4 時、休日判定の日付、
アクアラインの時間帯、首都高の入口時刻、料金改定日）が `(早いラベルの時刻, 遅いラベルの時刻 + horizon]` に入ると、
時刻の早さで支配しない（`boundary_between`）。horizon = 一般道だけの所要時間 − 遅いラベルの時刻。

問題: 深夜の前後に出発すると、ほとんどの比較で支配できなくなり、ループの多い道路網（首都高のような環状）では
ラベル数が爆発する。架空の 500 ノードで 1 時間以上終わらなかった。今は `max_labels` を超えたら近似モード
（時刻の境目を無視して時刻で支配）にやり直している。

前提（変えてよいかも含めて検討してほしい）:
- 経路は walk（U ターンと入口 = 出口のランだけ禁止）。鍵に直前ノードを入れている。
- 料金は「ラン」単位。NEXCO は入口・出口の時刻で休日・深夜を判定（現行）。首都高は入口時刻だけ。
  料金所の道路は料金所を通った時刻。見直し後の深夜割引は 22〜5 時に走った距離。
- 対象は日本全国（ノード 2,000〜5,000 程度）、乗る・降りる IC の候補は各 10〜20。1 回の検索は数秒以内にしたい。

## 考えてほしいこと
1. 正確さ（総当たりと同じパレート集合）を保ったまま、ラベル数を抑える方法。例:
   - 境目の判定を「そのラベルのこれから先の料金に効く出来事（今のランの出口、今後のランの入口、料金所）」に絞る
   - 料金の下限・上限を使った枝刈り（ランの料金の下限、見つかった解による大域的な支配）
   - 時間を境目で区切った時間拡大グラフ、SA/PA で待てる前提の導入（待つ案を出すこと自体は利用者にも有益）
   - そのほかの文献上の手法（時間依存の資源制約付き最短路など）
2. それぞれの正しさの根拠（なぜ総当たりと一致するか）と、計算量の見込み、実装の手間。
3. おすすめの方針を 1 つと、その実装手順・テストの方法。
