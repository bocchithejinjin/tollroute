# Codex タスク 05: 探索の高速化（docs/exact-search-design.md の手順 1〜3 の一部を実装）

## 範囲
あなたが書いた `docs/exact-search-design.md` の推奨方針のうち、次を `engine/search.py`（必要なら `engine/tariffs.py`）に実装する。

1. **時間下限 h(v)**: 出口候補 → 目的地の一般道時間を仮想辺にし、目的地から逆向き Dijkstra（U ターン・ラン終了条件は緩めてよい）。
   既存の引数 `lower_bound_min` が渡されたら、各ノードで h(v) との大きいほうを使う（どちらも正当な下限である前提）。
2. **完成案による大域的な支配**: `B(L) = (t + h(v), closed + pending + 将来の料金所の下限)` が、登録済みの完成案（一般道案を含む）に時間・料金とも支配されたら捨てる。
   キューは `t + h(v)` 順、取り出し時にも再判定。料金所の将来下限は、料金所・方向ごとの全時刻の最小額を辺の重みにした逆向き Dijkstra。ほかの料金の下限は 0 円でよい（NEXCO・OD の現在ラン下限は今回は不要）。
3. **比較の局所化（首都高と料金所だけ）**: 時刻の境目で支配を止める判定（`boundary_between` を使う部分）を、
   「そのラベルの続きで料金に効く出来事」に絞る。首都高は今のランの継続中は 0 時・4 時・改定日を気にしなくてよい（入口で確定済み）。
   後続の首都高ランへの入口、料金所の通過だけが判定の対象。NEXCO は今のまま保守的に（今の判定を維持）。
   出来事までの最短時間 `d_x(v)` と、出来事から目的地までの最短残り時間 `r_x` で判定の時間範囲を狭める（設計書 2 章）。

`max_labels` を超えたら近似モードでやり直す今の仕組みは**残す**（利用者には「近似」と表示して答えを返す方針。Claude の判断）。
`Searcher.stats` に、生成ラベル数・展開数・枝刈り理由別の件数を追加する。

## 正しさの確認（必須）
- 既存の `engine/tests/` がすべて通ること（`./.venv/Scripts/python -m pytest -q engine`、Windows の venv。または `python -m pytest -q engine`）。
- 設計書 4 章の境界ケースのうち、首都高と料金所に関するもの（首都高の同じランが 0 時をまたいでも支配が働く／後続の料金所が境目を挟むと安いほうが残る／改定日の直前・ちょうど・直後）を、総当たりとの照合テストとして追加する。
- 小さい乱数網での総当たり照合（既存の `test_search_matches_brute` 等）を、出発時刻を増やして回す。
