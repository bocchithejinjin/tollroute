# 一般道の所要時間の見積もり（道路交通センサスの平均旅行速度）

2026-11-24 時点。実装は `routes/speed.py` と `routes/travel.py`（`OsrmProvider`）。

## 結論
一般道の所要時間は、**OSRM で求めた経路の距離 ÷ 通る地域の平均旅行速度**で見積もる。平均旅行速度は、国の道路交通センサスの地域別・時間帯別の値を使う。これまでの「OSRM の時間 × 一律 1.8 倍」と比べると、Google の実測との差は最大 47% から最大 12% に縮んだ。係数は実測に合わせていない（センサスの値をそのまま使っている）。

## 何が問題だったか
OSRM の時間は、信号待ちや渋滞のない値。都市部では実際の 2〜3 倍速く出る。一律の 1.8 倍では、都心寄りの区間（例: 玉川→新宿駅）で実際の半分ほどの時間になっていた。そのため自作エンジンは、早めに高速を降りて一般道を走る案を「速い」と誤って選んでいた。

## 見積もり方
1. OSRM の Table API で、経路の距離と渋滞なしの時間を求める（`annotations=duration,distance`、有料道路を除く）。
2. 始点と終点を結ぶ直線上の 5 点を、手元の住所辞書（jageocoder）で市区町村に逆引きし、センサスの地域に当てる（例: 新宿区 → 東京都（特別区）、横浜市 → 横浜市、藤沢市 → 神奈川県（横浜市、川崎市、相模原市を除く））。
3. 距離を 5 等分し、各点の地域の速度で走るとして時間を合計する。渋滞なしの時間より速くはしない。
4. 時間帯は出発日時で決める。目的地側の区間は、着くころの時刻（直線距離 × 1.3 を時速 30km で走るとした目安）で決める。

| 時間帯 | 使う速度 |
|---|---|
| 平日の 7〜9 時・17〜19 時 | センサスの混雑時（朝夕）旅行速度 |
| それ以外の 7〜19 時（休日の昼も） | センサスの非混雑時（昼間）旅行速度 |
| 19〜7 時 | 非混雑時 × 1.25（センサスに夜間の値がないための推定。**未確認**） |

主な地域の値（令和3年度、一般道路計）:

| 地域 | 混雑時 | 非混雑時 |
|---|---|---|
| 東京都（特別区） | 13.9 km/h | 17.0 km/h |
| 東京都（市郡部） | 17.3 km/h | 20.5 km/h |
| 横浜市 | 16.4 km/h | 21.1 km/h |
| 川崎市 | 14.9 km/h | 19.5 km/h |
| 神奈川県（横浜市、川崎市、相模原市を除く） | 20.3 km/h | 24.6 km/h |

全国 85 地域の値は `routes/census_speeds.json`（`tools/update_census_speeds.py` で CSV から作る。出典は NOTICE.md）。

## Google の実測との比較（2026-11-24 火曜 9:15〜9:20、有料道路を避ける経路）

| 区間 | 旧（OSRM × 1.8） | 新（センサス・非混雑時） | Google |
|---|---|---|---|
| 横浜駅→新宿駅 | 76.2 分（−18%） | 103.2 分（+10%） | 93.4 分 |
| 八王子駅→新宿駅 | 88.2 分（−19%） | 115.9 分（+6%） | 109.1 分 |
| 横浜駅→港北 IC 付近 | 29.8 分（+2%） | 27.0 分（−8%） | 29.4 分 |
| 横浜駅→羽沢 IC 付近 | 14.5 分（−8%） | 13.9 分（−12%） | 15.8 分 |
| 玉川 IC 付近→新宿駅 | 29.6 分（−47%） | 49.8 分（−11%） | 55.8 分 |

- 測定は 5 区間・1 つの時間帯だけ。夜間・休日・混雑時は、Google でまだ確かめていない。
- 区間ごとに、Google の値を手で読み取って比べた（Google の結果は保存していない）。

## 検索結果への影響（自作エンジン、平日 9:15 発）
- 横浜駅→新宿駅（予算 1,000 円）: 最速 57 分 → 76 分（どちらも羽沢→玉川 390 円）。一般道だけは 76 分 → 103 分。
- 八王子駅→新宿駅（1,500 円）: 一般道が遅く見積もられるので、首都高で新宿まで行く案（八王子IC→新宿）が最速になった。
- 23 時発は、一般道だけで 横浜→新宿 83 分、八王子→新宿 93 分。これまでは時刻によらず同じ値だった。

## 住所辞書がないとき
住所辞書（`data/jageocoder/db`）がないとき、または `LOCAL_SPEED_MODEL=factor` のときは、従来どおり OSRM の時間を `LOCAL_CONGESTION_FACTOR`（既定 1.8）倍する。

- 逆引きには、辞書の中の逆引き用の索引（`rtree.dat`・`rtree.idx`）が要る。`python tools/build_reverse_index.py` で作る（この PC では約 5 分）。索引がなければ従来の係数に戻す（検索中に索引作りで止まらないように）。サーバーへ移すときは、索引ごと転送するか、デプロイのときに 1 回作る。
- 索引ができたあとの逆引きは、1 回 約 4 ミリ秒（約 1km 単位でキャッシュ）。

## 残っている課題
- 夜間・休日の速度の根拠（いまは推定）。Google の上限に余裕があるときに、時間帯を変えて測る。
- 出発時刻をずらす提案（±2 時間）では、一般道の時間を出発時刻のものから変えていない（問い合わせ回数を抑えるため）。
- 高速道路の区間の所要時間は、道路ごとに一定の速さのまま（Google と比べて短く出る。例: 羽沢→玉川で約 8 分）。
