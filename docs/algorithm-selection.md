# 探索アルゴリズムの選定

2026-11-23。結論: **多目的ラベル法（C）を採用**し、`engine/search.py` に実装した。

## 問題
出発地・目的地・出発日時・予算 B から、「一般道（出発地→乗る IC）＋高速（運営会社をまたいでよい）＋一般道（降りる IC→目的地）」のうち、料金 ≦ B で到着が最も早いものを求める。

難しいところ:
- 料金は区間の足し算にならない（利用 1 回ごとの定額、長距離の逓減、首都高は入口と出口の最短距離で決まる、料金表の道路）。
- 料金が時刻で変わる（深夜割引、休日割引の判定日、アクアラインの時間帯別料金、料金改定日）。遅く着いたほうが安くなることがある。

## 比べた方法（`explore/`）
| 方法 | 内容 |
|---|---|
| A | 乗る IC と降りる IC の組ごとに、最速の経路だけを見る |
| B | 組ごとに、速い順に上位 5 本の経路を見る（Yen の方法） |
| C | 所要時間と料金の両方で劣るラベルだけを捨てながら探索する（多目的ラベル法） |
| F | すべての経路を調べる（正解を求めるための総当たり） |

## 結果（架空の道路網、F を正解とした比較）
| ノード数 | 方法 | 間違えた問題 | 最大の損 | 平均時間 |
|---|---|---|---|---|
| 22 | A | 11.7% | 55 分 | 0.006 秒 |
| 22 | B | 0% | 0 | 0.16 秒 |
| 22 | C | 0% | 0 | 0.011 秒 |
| 28 | A | 13.3% | 48 分 | 0.014 秒 |
| 28 | B | 0% | 0 | 0.43 秒 |
| 28 | C | 0% | 0 | 0.019 秒 |

- A は「速いが高い経路」と「少し遅いが安い経路」が同じ組にあると、安いほうを見落とす。
- B はこの範囲では正しかったが、遅く、k 本で足りる保証もない。
- C は正しく速い。ただし、そのままでは時刻で料金が変わるときに正しい候補を捨てる弱点があった（下）。

## C を正しくするために入れた約束
1. **料金が切り替わる時刻をまたぐ可能性があるときは、「早く着く」ことを理由に捨てない。** 0 時をまたぐと、遅い経路のほうが深夜割引で安くなる例を見つけて、テストに固定した。
2. **料金所で確定した金額を比べる。**（Codex レビュー r01）
3. **経路は「その場での U ターン」と「乗った IC でそのまま降りる」だけを禁止し、ほかの再訪は認める。** 来た方向を比べるグループの鍵に入れる。同じ IC に戻れないとすると、先に着いたラベルが後のラベルの続きをまねできず、正しい候補を捨てることがあった。（Codex レビュー r01）
4. **距離は区分（普通・大都市近郊、割引の対象か）ごとにすべて比べる。** 「距離が多いほど料金が高い」が成り立つ単価の組み合わせかを、料金プールが起動時に確かめる。（Codex レビュー r01）
5. 見直し後の深夜割引（22〜5 時に走った分だけ割引）を有効にしたときは、その時間帯に走った距離も比べる鍵に入れる。

それぞれの約束について、外すとテストが失敗することを確かめた（`engine/tests/test_search.py`）。正しさは、本番の料金規則で、深夜・休日・料金改定日をまたぐ出発時刻を含めて総当たりと照合している。
